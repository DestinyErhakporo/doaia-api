Every endpoint requires an API key sent as a bearer token in the `Authorization` header, over HTTPS.

```http Header format
Authorization: Bearer YOUR_DOAIA_API_KEY
```

## Example request

<CodeGroup>

```bash cURL
curl 'https://api.example.com/v1/workflows' \
  -H 'Authorization: Bearer YOUR_DOAIA_API_KEY'
```

```javascript JavaScript
const response = await fetch("https://api.example.com/v1/workflows", {
  headers: { Authorization: "Bearer YOUR_DOAIA_API_KEY" },
});
const workflows = await response.json();
```

```python Python
import requests

response = requests.get(
    "https://api.example.com/v1/workflows",
    headers={"Authorization": "Bearer YOUR_DOAIA_API_KEY"},
    timeout=30,
)
workflows = response.json()
```

</CodeGroup>

## Handle keys safely

- Load keys from environment variables or a secrets manager. Never commit them to source control.
- Never send keys over plain HTTP or embed them in client-side code.
- Replace the placeholder `YOUR_DOAIA_API_KEY` with your own value in real clients. In this documentation it is not a real credential.

## Authentication errors

| Status | Code | Meaning |
| --- | --- | --- |
| `401` | `UNAUTHENTICATED` | The key is missing, malformed or invalid. |
| `403` | `FORBIDDEN` | The key is valid but not permitted to perform the action, for example changing a predefined workflow. |

See [Errors](/docs/reference/errors) for the full error envelope.
