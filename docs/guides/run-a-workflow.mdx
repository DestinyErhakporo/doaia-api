You start a run with `POST /v1/workflows/{workflow_id}/runs`. Start with asynchronous mode, then use synchronous mode for short workflows.

## Start an asynchronous run

<CodeGroup>

```bash cURL
curl -X POST 'https://api.example.com/v1/workflows/wf_customer_onboarding/runs' \
  -H 'Authorization: Bearer YOUR_DOAIA_API_KEY' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: example-run-001' \
  -d '{
    "execution_mode": "async",
    "input": { "customer_name": "Alex" }
  }'
```

```javascript JavaScript
const response = await fetch(
  "https://api.example.com/v1/workflows/wf_customer_onboarding/runs",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer YOUR_DOAIA_API_KEY",
      "Content-Type": "application/json",
      "Idempotency-Key": "example-run-001",
    },
    body: JSON.stringify({
      execution_mode: "async",
      input: { customer_name: "Alex" },
    }),
  },
);
const run = await response.json();
```

```python Python
import requests

response = requests.post(
    "https://api.example.com/v1/workflows/wf_customer_onboarding/runs",
    headers={
        "Authorization": "Bearer YOUR_DOAIA_API_KEY",
        "Idempotency-Key": "example-run-001",
    },
    json={"execution_mode": "async", "input": {"customer_name": "Alex"}},
    timeout=30,
)
run = response.json()
```

</CodeGroup>

Expect `202 Accepted`:

```json Accepted run
{
  "id": "run_01JXYZ123",
  "workflow_id": "wf_customer_onboarding",
  "workflow_version": 1,
  "status": "queued",
  "execution_mode": "async",
  "attempt": 1,
  "original_run_id": null,
  "created_at": "2026-11-22T18:15:00Z",
  "started_at": null,
  "completed_at": null,
  "cancel_requested_at": null,
  "failure": null
}
```

Next, [inspect the run](/docs/guides/inspect-a-run) until it reaches a terminal state.

## Start a synchronous run

Set `execution_mode` to `sync` and, optionally, `wait_timeout_seconds` (1 to 30).

```bash Synchronous run
curl -X POST 'https://api.example.com/v1/workflows/wf_customer_onboarding/runs' \
  -H 'Authorization: Bearer YOUR_DOAIA_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "execution_mode": "sync",
    "wait_timeout_seconds": 20,
    "input": { "customer_name": "Alex" }
  }'
```

## 200 versus 202

| Response | Meaning | What to do next |
| --- | --- | --- |
| `200` | The run finished within the wait. The body includes `result` when `status` is `succeeded`. | Use `result`. If `status` is `failed`, read `failure`. |
| `202` | The run was accepted, or the wait expired while it keeps running. | Poll the returned run ID. |

## Other responses

| Status | Meaning |
| --- | --- |
| `400` | Malformed request, or `wait_timeout_seconds` used with `async` or above 30. |
| `404` | The workflow does not exist. |
| `409` | The workflow is archived (`INVALID_STATE`), or the idempotency key was used with a different request (`IDEMPOTENCY_CONFLICT`). |
| `422` | The input does not match the workflow `input_schema`. |

See [Execution modes](/docs/concepts/execution-modes) for how idempotency works.
