## Cancel a run

```bash Request cancellation
curl -X POST 'https://api.example.com/v1/runs/run_01JXYZ123/cancel' \
  -H 'Authorization: Bearer YOUR_DOAIA_API_KEY'
```

| Status | Meaning | What to do next |
| --- | --- | --- |
| `202` | Cancellation was requested. It has not necessarily completed. | Poll the run until `status` is `cancelled`. |
| `404` | The run does not exist or has expired. | Check the run ID. |
| `409` | The run is already in a terminal state (`INVALID_STATE`). | Nothing to cancel. |

```json Cancellation requested
{
  "id": "run_01JXYZ123",
  "workflow_id": "wf_customer_onboarding",
  "workflow_version": 1,
  "status": "running",
  "execution_mode": "async",
  "attempt": 1,
  "original_run_id": null,
  "created_at": "2026-11-22T18:15:00Z",
  "started_at": "2026-11-22T18:15:01Z",
  "completed_at": null,
  "cancel_requested_at": "2026-11-22T18:15:03Z",
  "failure": null
}
```

## Retry a failed run

```bash Retry a run
curl -X POST 'https://api.example.com/v1/runs/run_01JXYZ150/retry' \
  -H 'Authorization: Bearer YOUR_DOAIA_API_KEY'
```

Expect `202 Accepted` with a **new** run. The original stays as it was.

```json Retry run
{
  "id": "run_01JXYZ151",
  "workflow_id": "wf_customer_onboarding",
  "workflow_version": 1,
  "status": "queued",
  "execution_mode": "async",
  "attempt": 2,
  "original_run_id": "run_01JXYZ150",
  "created_at": "2026-11-22T18:35:00Z",
  "started_at": null,
  "completed_at": null,
  "cancel_requested_at": null,
  "failure": null
}
```

The new run reuses the original input and workflow version. A run that was not `failed`, was already retried, or belongs to an archived workflow returns `409 INVALID_STATE`. If the retry fails too, retry the newest failed run.

See [Retries and cancellation](/docs/concepts/retries-and-cancellation) for the full rules.
